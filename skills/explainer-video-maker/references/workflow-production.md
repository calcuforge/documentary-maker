# Workflow — Production Phase (Steps 6-10)

> **Load when:** entering Step 6, or when the user asks about TTS, upscale, composition, render, or BGM.

## Step 6: Generate Per-Scene TTS + Merge

**Outputs (per scene):** `scenes/{s}/narration.wav` (48 kHz mono), `scenes/{s}/narration.srt`, `scenes/{s}/timing.json`
**Outputs (video level):** `narration_audio.wav`, `narration_audio.srt`, root `timing.json`

TTS is generated **per scene** — each scene's narration is one synthesis job, so a scene can be re-voiced without touching the rest of the video.

### `tts synth` — single-call synthesis (recommended for agents)

The simplest way to synthesize TTS: pass the prefs file and TTS parameters, and the command auto-routes to the correct backend. No `--backend` flag needed — it reads `tts.backend` from the config.

```bash
python3 "$SKILL_DIR/scripts/cli.py" tts synth \
  --prefs "projects/$P/project_prefs.yaml" \
  --text "1998年9月2日，瑞士航空111号班机从纽约肯尼迪机场起飞。" \
  --voice-file "projects/$P/voice_reference.wav" \
  --speed 0.9 \
  --output "projects/$P/videos/$V/scenes/hero/narration.wav"
```

**Arguments:**

| Arg | Required | Description |
| --- | --- | --- |
| `--prefs` | yes | Path to `project_prefs.yaml`. Reads `tts.backend`, `tts.http.*`, `workflows.tts`. |
| `--text` | yes | Narration text to synthesize. |
| `--voice-file` | yes | Reference voice WAV for cloning. |
| `--speed` | no | Speech speed multiplier. Falls back to `tts.http.speed` in prefs if set, otherwise backend default. |
| `--output` | no | Output WAV path. Defaults to `<cwd>/tts_output.wav`. Output is always 48 kHz mono pcm_s16le. |

**Backend routing** is automatic:

| `tts.backend` value | What happens |
| --- | --- |
| `comfyui_indextts` (default) | Calls `comfyui-scheduler run -w index_tts_2 -i '{"content":"<text>","voice_file":"<path>"}'` |
| `http_server` | POSTs multipart/form-data (`input`, `speed`, `voice_file`) to `tts.http.url` |

The agent does NOT need to know which backend is configured — just call `tts synth` and it handles the routing.

### Backends (reference)

- **ComfyUI index_tts (default)** — calls `comfyui-scheduler run -w index_tts_2 -i '{"content":"<scene narration>","voice_file":"<abs path>"}'` per scene.
- **HTTP TTS server** — `--backend http_server`: multipart/form-data POST with fields `input` (text), `speed` (float), and `voice_file` (WAV file upload) to `tts.http.url` per scene. Response body is raw audio bytes. Requires `BACKEND_PROXY_ENDPOINT` env var.

**Choosing the backend:**
- `comfyui_indextts` (default) — uses ComfyUI index_tts_2 workflow. No extra config needed beyond `tts.voice_file`.
- `http_server` — set `tts.backend: http_server` in `project_prefs.yaml` and `tts.http.url` to the TTS endpoint. Export `BACKEND_PROXY_ENDPOINT` before running. Add `--backend http_server` to every `tts run` command, or set it once in project prefs so the script reads it automatically.

**Prereq:** `project_prefs.tts.voice_file` must point to an existing reference audio file — normally `projects/{p}/voice_reference.wav` (generated by Step 0 voice design). IndexTTS uses it to clone the speaker's timbre; all scenes share the same voice.

Config:
```yaml
tts:
  backend: http_server        # or comfyui_indextts (default)
  voice_file: projects/aviation-disaster-horizontal/voice_reference.wav
  http:
    url: ${BACKEND_PROXY_ENDPOINT}
    speed: 1.0                # speech speed multiplier
```

### (a) Parallel per-scene (recommended)

Scenes are independent TTS jobs — issue them as **parallel Bash calls** (one message, multiple tool calls), then merge. The `tts run` command reads `tts.backend` from `project_prefs.yaml` automatically; `--backend` is only needed to override.

```bash
# All backends — tts run auto-detects backend from project_prefs.yaml:
python3 "$SKILL_DIR/scripts/cli.py" tts run --project $P --video $V --scene hero
python3 "$SKILL_DIR/scripts/cli.py" tts run --project $P --video $V --scene timeline
python3 "$SKILL_DIR/scripts/cli.py" tts run --project $P --video $V --scene impact

# Optional: override backend explicitly (rarely needed):
# python3 ... tts run ... --backend http_server

# Once all scenes are done:
python3 "$SKILL_DIR/scripts/cli.py" tts merge --project $P --video $V
```

**Single-call alternative** — `tts synth` for testing one line without a scene directory:

```bash
python3 "$SKILL_DIR/scripts/cli.py" tts synth \
  --prefs "projects/$P/project_prefs.yaml" \
  --text "测试语音合成。" \
  --voice-file "projects/$P/voice_reference.wav" \
  --output /tmp/test.wav
```

### (b) Sequential all-scenes

```bash
python3 "$SKILL_DIR/scripts/cli.py" tts run --project $P --video $V
```

Synthesizes every scene in script order, then runs the merge automatically. Simpler; slower.

### What each scene run does

1. Synthesizes the scene narration → downloads the audio.
2. Normalizes to **48 kHz mono pcm_s16le** WAV at `scenes/{s}/narration.wav` (required so the merge can use `ffmpeg -c copy` — lossless, no re-encode).
3. Runs `estimate_timing.py --scene {s}`:
   - `ffprobe` the scene WAV → scene `total_duration` (the scene's audio-master clock — exact, not estimated).
   - Distribute shot durations by `duration_hint_seconds` (even split without hints); remainder → last shot.
   - Split narration into SRT cues at sentence-final punctuation; cue times by char weight (CJK 1.0 / ASCII 0.5 / punct 0.0), **relative to the scene start**.
   - Write `scenes/{s}/narration.srt` + `scenes/{s}/timing.json` (`shots` list).

### What the merge does

1. `ffmpeg -f concat -safe 0 -c copy` all scene WAVs (script order) → `narration_audio.wav`.
2. Concatenate scene SRTs with per-scene time offsets, renumbered → `narration_audio.srt`.
3. Aggregate scene timings → root `timing.json` (`{total_duration, fps, total_frames, chapters: [...], scenes: [...]}`).

### Audio-master clock checks

```bash
# Scene level — must be ~exact (timing comes straight from ffprobe):
ffprobe -v error -show_entries format=duration -of csv=p=0 "$VDIR/scenes/hero/narration.wav"
python3 -c "import json; print(json.load(open('$VDIR/scenes/hero/timing.json'))['total_duration'])"

# Video level — sum of scenes vs merged track (±0.5s):
python3 "$SKILL_DIR/scripts/cli.py" audit beats --video-dir "$VDIR"
```

If a scene drifts, re-run that scene's TTS + `tts merge`. Never splice scene WAVs manually — always through `tts merge` (offsets and 48 kHz normalization are enforced there).

### Regenerating one scene

Edit the scene's narration in `narration_script.yaml`, then:

```bash
python3 "$SKILL_DIR/scripts/cli.py" tts run --project $P --video $V --scene timeline
python3 "$SKILL_DIR/scripts/cli.py" tts merge --project $P --video $V
```

Only that scene's audio is re-synthesized. (Then re-render that scene + re-merge — Step 9.)

### Manual mode gate

Show the user each scene's audio file, the SRT preview (first 3 cues), and the timing summary (per-scene duration + shot split). Ask "Sounds right? Want to regenerate a scene?" before proceeding.

## Step 7: Upscale to Target Resolution

For each resolved image and video asset, decide whether to upscale:

| Tier | Target | Images | Videos |
| --- | --- | --- | --- |
| speed | 1080p | 1280×720 → 1920×1080 | 854×480 → 1920×1080 |
| speed | 4k | 1280×720 → 3840×2160 | 854×480 → 3840×2160 |
| quality | 1080p | skip (already 1920×1080) | 1280×720 → 1920×1080 |
| quality | 4k | 1920×1080 → 3840×2160 | 1280×720 → 3840×2160 |

Vertical videos are 1080p only in v1.

### Batch ordering (same rule as Step 5)

Follow the same batch strategy from [workflow-assets.md#5b-prime-batch-execution-strategy](workflow-assets.md#5b-prime-batch-execution-strategy). Upscale jobs split into two sequential batches:

| Batch | Workflow | Input |
| --- | --- | --- |
| 7 | `nvidia_rtx_video_upscale` | All resolved video assets that need upscaling |
| 8 | `nvidia_rtx_image_upscale` | All resolved image assets that need upscaling |

**Video upscale always runs before image upscale** — video upscale is heavier and ties up the GPU longer. Finishing images last means the agent can start Step 8 (composition generation) while CPU-bound image upscale finishes.

### Image upscale (nvidia_rtx_image_upscale)

Magnification = target_long_side / source_long_side. For 1280×720 → 1920×1080, magnification = 1920/1280 = 1.5.

Within a batch, all image upscale calls are independent (different input files, same workflow). The agent MUST issue them in parallel:

```bash
# Batch 8 — two images in parallel (single message, multiple Bash calls)
python3 "$SKILL_DIR/scripts/cli.py" comfyui run \
  -w nvidia_rtx_image_upscale \
  -i '{"image_file":".../assets/hero_bg.png","magnification":1.5}' \
  --dest-dir "$VDIR/assets"

python3 "$SKILL_DIR/scripts/cli.py" comfyui run \
  -w nvidia_rtx_image_upscale \
  -i '{"image_file":".../assets/timeline_bg.png","magnification":1.5}' \
  --dest-dir "$VDIR/assets"
```

After all upscale jobs in one batch finish, update the manifest entries:

```bash
python3 "$SKILL_DIR/scripts/cli.py" assets update \
  --video-dir "$VDIR" --id hero_bg --upscaled
python3 "$SKILL_DIR/scripts/cli.py" assets update \
  --video-dir "$VDIR" --id timeline_bg --upscaled
```

### Video upscale (nvidia_rtx_video_upscale)

Same pattern; video workflows accept `file` input. Batch 7 runs before batch 8.

### Skip-upscale optimization

For quality tier + 1080p target on images: skip batch 8 entirely for images. Mark the manifest entry `upscaled: true` without running the workflow.

## Step 8: Generate Per-Scene Composition

**Outputs (per scene):** `scenes/{s}/scene.tsx`, `scenes/{s}/entry.tsx`, `scenes/{s}/composition.json`

```bash
python3 "$SKILL_DIR/scripts/cli.py" compose --project $P --video $V
```

This script:
1. Reads `project_prefs.yaml`, deep-merges the theme preset.
2. Reads `narration_script.yaml` (chapters → scenes → shots).
3. For every scene, writes three files under `scenes/{s}/`:
   - `composition.json` — the scene's shot designs, read at runtime via `staticFile`.
   - `scene.tsx` — a ShotComponent switch driven by `shot.component`, rendering the shot's material (`asset_id`) plus auxiliary layers (`overlays[]` via `OverlayLayer`, `data[]`, `text[]`). A `TransitionSeries` plays the shots in order with the audio-master clock math (shots scaled proportionally so the rendered total equals the scene's `timing.total_frames`). Imports all components from `<TEMPLATE_PATH>/src/components/index.js` (including `TransitionSeries`/`linearTiming`, re-exported by the template barrel).
   - `entry.tsx` — Composition registration; `calculateMetadata` reads `scenes/{s}/timing.json` for `durationInFrames`.
4. The render hint in the output lists the exact `npx remotion render` command per composition id.

`--public-dir` stays the video root at render time, so `staticFile("scenes/{s}/timing.json")`, `staticFile("scenes/{s}/narration.wav")`, `staticFile("scenes/{s}/narration.srt")`, and the shared `staticFile("assets/manifest.json")` all resolve. The shared template's `useAssets` reads `assets/manifest.json` via `staticFile` (per-video via `--public-dir`).

### Why not edit the shared template directly?

The template's `src/Video.js` ships with hardcoded literals and a flat-section model. Per-scene `scene.tsx` lives in the video dir, imports the template's component library, and supplies the shot-specific content. The shared template stays untouched (its barrel re-exports `TransitionSeries`/`linearTiming` so compositions outside the template's node_modules tree can import them).

### Default props applied

From project prefs (theme block) → Composition `defaultProps`:
- `primaryColor`, `backgroundColor`, `textColor`, `accentColor`
- `transitionType`, `transitionDuration` (applied between **shots** within a scene)
- `scaleFactor` (1 for 1080p, 2 for 4k)
- `orientation` ("horizontal" / "vertical")
- `enableAudio: true` (scene audio is the master clock — never disable unless testing)
- `enableSubtitles: true` (scene SRT burned in by default)
- `showProgressBar: false` (each scene would reset 0→100%; enable for in-scene shot progress)
- `bgmVolume: 0` (BGM is mixed via FFmpeg in Step 10; scene renders never carry BGM)

### Manual mode gate

Show the user the generated `scene.tsx` + `entry.tsx` for each scene. The user can request a regeneration after editing `narration_script.yaml`. Don't render until "continue".

## Step 9: Render Scenes + Ordered Merge

**Outputs:** `scenes/{s}/scene.mp4` (per scene; narration + subtitles baked in) → `output.mp4` (all scenes merged, lossless; 1920×1080 / 3840×2160 / 1080×1920, 30 fps)

### 9a. Render each scene

Run from the template directory so node_modules resolves:

```bash
TEMPLATE_PATH="<abs path to remotion-video-template>"
VDIR="<abs path to video dir>"
COMP_ID=MainVideo  # or MainVideo4K / MainVideoVertical per project prefs

# One render per scene:
cd "$TEMPLATE_PATH" && npx remotion render \
  "$VDIR/scenes/hero/entry.tsx" \
  "$COMP_ID" \
  "$VDIR/scenes/hero/scene.mp4" \
  --public-dir "$VDIR" \
  --video-bitrate 16M
```

The `--public-dir` flag points at the video dir so every `staticFile(...)` resolves (scene files under `scenes/{s}/`, shared assets under `assets/`).

**Parallelism:** scene renders are independent — they can be issued as parallel Bash calls. But each Remotion render already uses all CPU cores, so cap concurrency at ~2 on typical machines (or run sequentially). The scheduler gains are mainly from overlapping GPU-bound upscale (Step 7) with early scene renders.

### 9b. Verify per-scene sync

```bash
python3 "$SKILL_DIR/scripts/cli.py" audit beats --video-dir "$VDIR"
```

Flags any scene where `scene.mp4` vs `narration.wav` drifts >0.5s (stale render → re-compose + re-render that scene).

### 9c. Merge scenes (ordered, lossless)

```bash
python3 "$SKILL_DIR/scripts/cli.py" merge --project $P --video $V
```

Writes `concat.txt` in script order and runs `ffmpeg -f concat -safe 0 -c copy` → `output.mp4`. Before concatenating, it ffprobes every scene render and **fails on encoding-parameter mismatch** (codec / width / height / pix_fmt / fps / sample rate / channels). Mismatches happen only if scenes were rendered with different composition ids or flags — fix by re-rendering all scenes the same way. Scene joins are hard cuts by design (transitions run between shots *inside* a scene).

### 9d. Verify the merged video

```bash
VID=$(ffprobe -v error -show_entries format=duration -of csv=p=0 "$VDIR/output.mp4")
WAV=$(ffprobe -v error -show_entries format=duration -of csv=p=0 "$VDIR/narration_audio.wav")
python3 -c "v,w=float('$VID'),float('$WAV'); print(f'video={v:.2f}s audio={w:.2f}s diff={abs(v-w):.2f}s'); exit(1 if abs(v-w)>0.5 else 0)"

ffprobe -v quiet -show_entries stream=width,height -of csv=p=0 "$VDIR/output.mp4"
# Expected: 1920,1080 (horizontal 1080p) / 3840,2160 (4k) / 1080,1920 (vertical)
```

If drift >0.5s, locate the offending scene via `audit beats`, re-render it, and re-run `merge`.

## Step 10: Mix BGM

**Output:** `video_with_bgm.mp4`

BGM config from `project_prefs.bgm`:
- `volume` (0 to 1.0, default 0.12)
- `track` (absolute path to mp3, or null for no BGM)
- `loop` (true = `-stream_loop -1`)

### Single-write rule

BGM is layered **after** the scene merge, via FFmpeg — per-scene renders never carry BGM (the generated `scene.tsx` has no BGM block; `defaultProps.bgmVolume = 0` is reserved/unused). This keeps scene renders re-usable: re-rendering one scene never changes the music bed. Step 10 mixes BGM onto `output.mp4` via FFmpeg `amix`.

### Mix

```bash
BGM_VOL=$(python3 -c "import yaml; print(yaml.safe_load(open('$PREFS'))['bgm']['volume'])")
BGM_TRACK=$(python3 -c "import yaml; print(yaml.safe_load(open('$PREFS'))['bgm']['track'])")

if [ -z "$BGM_TRACK" ] || [ ! -f "$BGM_TRACK" ]; then
  # No BGM — just rename output.mp4
  cp "$VDIR/output.mp4" "$VDIR/video_with_bgm.mp4"
  exit 0
fi

cp "$BGM_TRACK" "$VDIR/bgm.mp3"

ffmpeg -y \
  -i "$VDIR/output.mp4" \
  -stream_loop -1 -i "$VDIR/bgm.mp3" \
  -filter_complex "[0:a]volume=1.5[a1];[1:a]volume=${BGM_VOL}[a2];[a1][a2]amix=inputs=2:duration=first:normalize=0[aout]" \
  -map 0:v -map "[aout]" \
  -c:v copy -c:a aac -b:a 192k \
  "$VDIR/video_with_bgm.mp4"
```

**Why these values:**
- `volume=1.5` (narration): lifts TTS audio from ~-26 dB to ~-22 dB without clipping.
- `volume=$BGM_VOL` (BGM, default 0.12 = ~-18 dB): ~18 dB headroom under narration.
- `normalize=0`: prevents `amix` from halving the narration volume.

### Verify loudness

```bash
ffmpeg -i "$VDIR/video_with_bgm.mp4" -af volumedetect -f null - 2>&1 | grep -E "mean_volume|max_volume"
# Target: mean -20 to -22 dB, max -1 to -3 dB
```

If too quiet, add `loudnorm=I=-16:TP=-1.5:LRA=11` for EBU R128 normalization (slower).
